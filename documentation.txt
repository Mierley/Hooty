ТЕХНИЧЕСКАЯ ДОКУМЕНТАЦИЯ: Program.cs
================================================================================

ОБЗОР
-----
Program.cs является точкой входа ASP.NET Core приложения Innohoot. 
Файл конфигурирует веб-приложение, регистрирует сервисы и настраивает 
middleware pipeline.

Версия: Minimal Hosting Model (ASP.NET Core 6.0+)
Язык: C# (.NET)

================================================================================
ЗАВИСИМОСТИ
================================================================================

Используемые пространства имен:
- Innohoot.DataLayer
- Innohoot.DataLayer.Services.Implementations
- Innohoot.DataLayer.Services.Interfaces
- Microsoft.EntityFrameworkCore
- Newtonsoft.Json

Внешние пакеты:
- Entity Framework Core - ORM для работы с PostgreSQL
- Newtonsoft.Json - сериализация/десериализация JSON
- AutoMapper - маппинг объектов
- SignalR - real-time коммуникация
- Swagger - документация API

================================================================================
АРХИТЕКТУРА ПРИЛОЖЕНИЯ
================================================================================

1. ИНИЦИАЛИЗАЦИЯ (строки 9-11)
   - Создание WebApplicationBuilder для конфигурации приложения
   - Объявление переменной для CORS политики

2. КОНФИГУРАЦИЯ СЕРВИСОВ
   
   2.1 CORS ПОЛИТИКА (строки 13-19)
       Политика: "CorsPolicy"
       Разрешения:
       - Любые источники (origins)
       - Любые HTTP методы (GET, POST, PUT, DELETE и т.д.)
       - Любые заголовки
       
       ⚠️ ПРЕДУПРЕЖДЕНИЕ: Конфигурация AllowAnyOrigin() небезопасна 
       для production окружения. Рекомендуется ограничить список 
       разрешенных источников.

   2.2 SIGNALR (строка 30)
       Подключение SignalR для WebSocket коммуникации в реальном времени.
       Применение: Синхронизация данных между клиентами (например, 
       обновление результатов голосования).

   2.3 CONTROLLERS И СЕРИАЛИЗАЦИЯ JSON (строки 32-36)
       Конфигурация:
       - Регистрация MVC контроллеров
       - Использование Newtonsoft.Json вместо System.Text.Json
       - ReferenceLoopHandling.Ignore - игнорирование циклических ссылок
       - Сохранение оригинального регистра имен свойств

   2.4 SWAGGER ДОКУМЕНТАЦИЯ (строка 47)
       Генерация OpenAPI (Swagger) документации для REST API.
       Доступ: /swagger endpoint

   2.5 REPOSITORY PATTERN (строка 49)
       IDBRepository -> DBRepository
       Lifetime: Scoped (один экземпляр на HTTP запрос)

   2.6 DOMAIN СЕРВИСЫ (строки 52-57)
       Lifetime: Transient (новый экземпляр при каждом запросе)
       
       Зарегистрированные сервисы:
       - IPollService -> PollService (управление опросами)
       - ISessionService -> SessionService (управление сессиями)
       - IUserService -> UserService (управление пользователями)
       - IVoteRecordService -> VoteRecordService (обработка голосов)
       - IOptionService -> OptionService (управление вариантами)
       - IPollCollectionService -> PollCollectionService (коллекции опросов)

   2.7 AUTOMAPPER (строка 59)
       Регистрация профилей маппинга для автоматического преобразования 
       между сущностями и DTO.
       Профиль: AppMappingProfile

   2.8 БАЗА ДАННЫХ (строки 62-65)
       ORM: Entity Framework Core
       СУБД: PostgreSQL (Npgsql провайдер)
       Connection String: Берется из конфигурации под ключом "Default"
       Lifetime: Scoped (по умолчанию для DbContext)

3. СОЗДАНИЕ ПРИЛОЖЕНИЯ (строка 67)
   Компиляция конфигурации и создание экземпляра WebApplication

4. КОНФИГУРАЦИЯ HTTP PIPELINE

   4.1 ENVIRONMENT-ЗАВИСИМАЯ КОНФИГУРАЦИЯ (строки 70-76)
       Для Non-Development окружения:
       - HSTS (HTTP Strict Transport Security) - принудительное HTTPS
       - Swagger UI - интерактивная документация API
       
       ⚠️ ПРИМЕЧАНИЕ: Логика кажется инвертированной - обычно Swagger 
       включается только в Development режиме.

   4.2 MIDDLEWARE PIPELINE (строки 78-82)
       Порядок выполнения:
       1. UseHttpsRedirection - перенаправление HTTP → HTTPS
       2. UseStaticFiles - обслуживание статических файлов (React)
       3. UseRouting - определение endpoint'ов
       4. UseCors - применение CORS политики "CorsPolicy"

   4.3 ROUTING КОНФИГУРАЦИЯ (строки 84-88)
       Паттерн: /{controller}/{action}/{id?}
       - action по умолчанию: Index
       - id - опциональный параметр
       
       Fallback: Все неизвестные маршруты → index.html
       (поддержка SPA клиент-стороннего роутинга React)

   4.4 ЗАПУСК ПРИЛОЖЕНИЯ (строка 89)
       Запуск веб-сервера и начало прослушивания HTTP запросов

================================================================================
ПАТТЕРНЫ ПРОЕКТИРОВАНИЯ
================================================================================

1. Dependency Injection (DI)
   Все сервисы регистрируются через встроенный DI контейнер ASP.NET Core

2. Repository Pattern
   Использование IDBRepository для абстрагирования работы с данными

3. Service Layer Pattern
   Бизнес-логика инкапсулирована в отдельных сервисах

4. DTO Pattern
   Использование AutoMapper для преобразования между моделями и DTO

ТИПИЧНЫЕ ПРОБЛЕМЫ:

Проблема: Connection refused
Причина: PostgreSQL не запущен
Решение: Запустить БД

Проблема: CORS ошибка
Причина: Неправильная политика
Решение: Проверить origin клиента

Проблема: 404 для API
Причина: Неверный routing
Решение: Проверить паттерн маршрута

Проблема: Циклическая ссылка JSON
Причина: Навигационные свойства EF
Решение: Уже решено через ReferenceLoopHandling.Ignore
